Core Entities Created:

  Sport
  ├── name (e.g., "Soccer")
  └── external_id

  Tournament (League)

  ├── sport_id

  ├── home_team_id
  ├── away_team_id

  ├── scheduled_at

  ├── fixture_id
  ├── name (e.g., "Soccer - Match Winner")

  ├── market_group_id
  ├── name (e.g., "Winner")
  └── selection_options

  Market
  ├── fixture_id
  ├── template_id

  ├── market_id
  ├── name (e.g., "1", "X", "2")
  ├── odds
  └── settled_result (boolean)

  OddsSnapshot
  ├── market_id
  ├── timestamp
  ├── odds (decimal value)

3.1 TEAM STATISTICS SNAPSHOT GENERATION
----------------------------------------

Purpose:
  Extract team performance characteristics at specific points in time
  (no future data leakage)

Current Status:
  ✓ Scripts available:
    - generate_historical_team_snapshots.py
    - sync_api_football_team_statistics.py

Process:

  1. Query APIFootballTeamStatistic records
  2. For each team-season combination:
     - Extract: wins, losses, draws, goals scored, goals conceded
     - Calculate: win rate, goal difference, points per game
     - Segment: home performance, away performance
     - Extract: clean sheets, failed to score
     - Extract: recent form (last 5 matches)
  3. Create historical snapshot tied to specific date
  4. Store HistoricalTeamSnapshot records

Database: HistoricalTeamSnapshot
  ├── team_id
  ├── snapshot_date
  ├── wins
  ├── losses
  ├── draws
  ├── goals_scored
  ├── goals_conceded
  ├── goal_difference
  ├── home_wins
  ├── home_draws
  ├── home_losses
  ├── away_wins
  ├── away_draws
  ├── away_losses
  ├── clean_sheets
  ├── failed_to_score
  └── recent_form (JSON)

Critical Principle:
  ⚠️ When generating features for a fixture on Date D:
     Only use team statistics available BEFORE Date D
     Never use data from after the fixture date

PART 4: TRAINING DATA PIPELINE
================================================================================

4.1 TRAINING EXAMPLE GENERATION
--------------------------------

Purpose:
  Convert settled betting selections into ML training rows
  One row = One fixture + market + selection

Current Status:
  ✓ Script available: generate_training_dataset.py
  ✓ Service: TrainingDatasetGeneratorService

Process:

  For each settled BetLeg:
    1. Verify fixture_id is linked
    2. Retrieve fixture features
    3. Retrieve odds snapshot (at bet placement time)
    4. Retrieve actual outcome
    5. Create TrainingExample record

Database: TrainingExample
  ├── bet_leg_id
  ├── fixture_id
  ├── market_type (enum: WINNER, TOTALS, BTTS, HANDICAP)
  ├── selection
  ├── odds_at_placement
  ├── features (JSON)
  ├── actual_outcome
  ├── was_correct (boolean)
  ├── profit_loss (decimal)
  ├── roi
  └── created_at

Labels Generated:
  ✓ Match Winner: 1/0/-1 (home win / draw / away win)
  ✓ Over/Under: 1/0 (over / under 2.5 goals)
  ✓ BTTS: 1/0 (yes / no)

Target: Market Prediction
  Each label represents what happened in the settled market
  Not what the bettor selected (selection becomes feature)

Structure:
  [Feature Vector] → [ML Model] → [Prediction]
  │                                      │
  └──────────────────────────────────────┘
        Compare against actual outcome


4.2 DATA LEAKAGE PREVENTION
----------------------------

Critical safeguards implemented:

  ✓ Temporal Ordering:
    Only use team stats from before fixture date

  ✓ Information Cutoff:
    Only use odds/data available at bet placement time

  ✗ NOT YET IMPLEMENTED - Feature Snapshot Storage:
    Should store exact feature vector at prediction time
    Allows debugging and retraining validation

  ✗ NOT YET IMPLEMENTED - Validation Set Separation:

5.3 MODEL EVALUATION FRAMEWORK (PLANNED)
-----------------------------------------

Do NOT evaluate using accuracy.

Metrics:
  ✓ ROI (Return on Investment)
  ✓ Yield (Profit / Turnover)
  ✓ CLV (Closing Line Value)
  ✓ Log Loss (Probability calibration)
  ✓ Brier Score (Predicted vs actual probability)
  ✓ Calibration Plot (Is 70% prediction actually 70% accurate?)

Success Criteria:
  • Model must beat market (positive CLV)
  • Confidence intervals must be narrow
  • Calibration must be accurate
  • Performance must persist on hold-out test set

Status: PENDING IMPLEMENTATION


5.4 INFERENCE PIPELINE (PLANNED)
---------------------------------

InferencePipeline
  Input: New fixture (not yet played)
  Process:
    1. Generate features using latest team stats
    2. Load trained model
    3. Generate probability predictions
    4. Compare against sportsbook odds
    5. Calculate implied value
    6. Flag: Value bet, Upset, Market mispricing

  Output:
    • Win probability
    • Over/Under probability
    • BTTS probability
    • Implied odds
    • Bookmaker odds
    • Value estimate
    • Confidence level
    • Recommendation (PLAY / PASS / STRONG PLAY)

  Status: FRAMEWORK IN PLACE

PART 14: KEY DATA FLOWS
================================================================================

Data Flow 1: Real-time Fixture Ingestion

  Stake API
    └─→ StakeGraphQLClient
    └─→ StakeFixtureService
    └─→ StakeFixtureSyncService
    └─→ Database: Fixture, MarketGroup, Market, Outcome, OddsSnapshot
    └─→ API exposure: GET /api/fixtures
    └─→ Frontend display


Data Flow 2: Historical Team Stats

  API-Football
    └─→ APIFootballClient
    └─→ SyncService
    └─→ Database: APIFootballTeamStatistic
    └─→ HistoricalTeamSnapshot generation
    └─→ Feature engineering (pre-fixture only)


Data Flow 3: Bet History → Training Data

  Stake User Bets
    └─→ StakeBetHistoryService
    └─→ Database: BetHistory, BetLeg
    └─→ LinkBetLegToFixture (PRIORITY: complete this)
    └─→ Generate features
    └─→ Database: TrainingExample
    └─→ ML pipeline input


Data Flow 4: New Fixture → Prediction

  Upcoming Fixture
    └─→ Generate features (using pre-fixture team stats)
    └─→ Load trained model
    └─→ Generate probability
    └─→ Compare vs sportsbook odds
    └─→ Calculate value
    └─→ Generate recommendation
    └─→ API exposure: GET /api/fixtures/{id}/predictions
    └─→ Frontend display + WebSocket update


Data Flow 5: Prediction → Automated Bet

  Recommendation (value bet identified)
    └─→ Bet builder applies selection criteria
    └─→ Slip generation worker
    └─→ Stake API: place bet
    └─→ Database: BetHistory record
    └─→ Track live + settlement
    └─→ Outcome validation
    └─→ Training data generation (for retraining)
